4. BẢNG PHÂN TÍCH VAI TRÒ CÁC CÔNG CỤ TRONG CHUỖI CI PIPELINE:
------------------------------------------------------------------------------------------------------------------------
| Công cụ           | Giai đoạn áp dụng     | Vai trò & Nhiệm vụ cốt lõi                                              |
|-------------------|-----------------------|--------------------------------------------------------------------------|
| **Git & GitHub**   | Source Control        | Quản lý phiên bản mã nguồn, ghi nhận lịch sử commit, kích hoạt webhook.   |
| **Jenkins**       | Orchestration (CI)    | Máy chủ điều phối tự động, thực thi các stages theo kịch bản Jenkinsfile|
| **Maven**         | Build & Dependency    | Quản lý thư viện phụ thuộc, biên dịch Java code, thực thi unit tests.   |
| **JUnit 5**       | Automated Testing     | Kiểm thử đơn vị tự động, đảm bảo tính đúng đắn logic của từng hàm.      |
| **SonarQube**     | Static Analysis (SAST)| Quét phát hiện bugs, lỗ hổng an ninh, code smells theo chuẩn Shift-Left. |
| **Nexus OSS**     | Binary Repository     | Kho lưu trữ tập trung các artifact nhị phân (.jar, .war), quản lý version|
------------------------------------------------------------------------------------------------------------------------

5. KẾT LUẬN & BÀI HỌC VẬN DỤNG THỰC TẾ:
   - **Tự động hóa hoàn toàn (Automation):** Thay vì các thao tác thủ công dễ nhầm lẫn (compile bằng tay, gửi file jar qua chat), CI Pipeline tự động thực hiện mọi bước ngay khi có code mới được commit.
   - **Phát hiện lỗi sớm (Fail Fast / Shift-Left):** Việc chạy Unit Test và SonarQube ngay trong CI giúp bắt lỗi logic và vi phạm quy chuẩn lập trình ngay từ giai đoạn phát triển, tiết kiệm chi phí sửa chữa.
   - **Tính nhất quán của Artifact:** File `.jar` sau khi build và test đạt chuẩn được đánh phiên bản cụ thể (ví dụ 1.0.0-SNAPSHOT) và đẩy vào kho Nexus tập trung, đảm bảo môi trường CD/Deploy sau này luôn lấy đúng bản nhị phân đã được kiểm định.
