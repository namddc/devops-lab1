         Stage 1: Checkout ➔ Kéo mã nguồn mới nhất từ GitHub qua Git SCM.
         Stage 2: Docker Build ➔ Tự động build Docker Image với tag động theo số build (${BUILD_NUMBER}).
         Stage 3: Docker Scan ➔ Quét lỗ hổng an ninh Docker Image bằng Docker Scout.
         Stage 4: Push to Registry ➔ Tự động đăng nhập Docker Hub qua Jenkins Credentials và push image lên registry.

         Stage 6: Verify Deploy ➔ Thực hiện curl tự động kiểm tra endpoint /health xác nhận deploy thành công.

4. BẢNG SO SÁNH CHUYÊN SÂU CI (BÀI 7) VS CD (BÀI 8):
------------------------------------------------------------------------------------------------------------------------
| Tiêu chí so sánh        | CI — Continuous Integration (Bài 7)     | CD — Continuous Delivery/Deployment (Bài 8)     |
|-------------------------|-----------------------------------------|-------------------------------------------------|
| **Mục tiêu cốt lõi**    | Kiểm tra mã nguồn có lỗi hay không      | Đóng gói và phát hành ứng dụng tới người dùng   |
| **Đầu vào (Input)**     | Mã nguồn thô (Source Code, Pull Request)| Mã nguồn đã pass CI / Artifact đã build         |
| **Đầu ra (Output)**     | File nhị phân (.jar, .war), test report | Docker Image, Container đang chạy trên Server   |
| **Công cụ chủ đạo**     | Maven, JUnit 5, SonarQube, Nexus        | Docker, Docker Compose, Docker Hub, Kubernetes   |
| **Câu hỏi giải quyết**  | "Code mới có an toàn để merge không?"   | "Hệ thống có sẵn sàng chạy trên Production?"    |
| **Tần suất thực thi**   | Liên tục trên mỗi commit / pull request | Sau khi CI hoàn thành hoặc khi phát hành release |
| **Khi xảy ra thất bại** | Lỗi logic code, vỡ test, lỗi bảo mật SAST| Lỗi đóng gói image, lỗi mạng, lỗi deploy container|
------------------------------------------------------------------------------------------------------------------------

5. BÀI HỌC VÀ KẾT LUẬN VẬN DỤNG:
   - **Tối ưu hóa tài nguyên:** Kỹ thuật Multi-stage build loại bỏ toàn bộ môi trường và cache build thừa, giảm kích thước image, tăng tốc độ tải và giảm diện tích tấn công (attack surface).
   - **Bảo mật Container (Container Hardening):** Việc không chạy dưới quyền user root trong container ngăn ngừa nguy cơ tấn công leo thang đặc quyền ra máy chủ host.
   - **Tự động hóa phát hành (Zero-downtime & Fast Rollout):** Jenkins CD Pipeline giúp tự động hóa từ khâu đóng gói đến triển khai, loại bỏ rủi ro sai sót do con người thao tác thủ công trên production.
